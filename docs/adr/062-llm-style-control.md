# ADR-062: MiMo 语音的风格控制交给 LLM 每轮决定

## Status

Accepted

## Date

2026-11-10

## Context

ADR-061 把小米 MiMo 接进语音时，用了一个写死的设置项 `ttsStyle`：用户填一句自然语言（例如「温柔、语速稍慢，带一点笑意」），每轮合成都把同一句作为 MiMo 的 `role: 'user'` 指令消息发过去。

问题在于「角色此刻该怎么说话」是会变的——被捏脸时该害羞、讲代码时该干练、深夜时该慵懒。写死一句等于把整轮对话的语气钉死在一个值上，用户想换语气就得手动改设置。

MiMo 的接口本身是按请求给指令的（`messages[0] = {role:'user', content: 风格指令}`），配合它的词表可以把「语调 / 情绪 / 音色质感 / 人设腔调 / 方言 / 导演式描述」写成一句话；这些信息对角色扮演来说正好是模型自己最清楚的东西。项目架构准则（ADR-047 一脉）也是「宿主不要替模型做规则化推导，把素材如实交给模型」。

同时有两个约束：

1. 只能动 MiMo。千问（OpenRouter `/audio/speech`）没有对应的指令消息，不能因为这次改动改变千问的提示词或请求形状。
2. 语气指令是控制信号，不能出现在气泡里、也不该污染历史正文；但历史需要留痕，否则模型记不住自己上一轮是什么语气。

## Decision

1. **删掉 `ttsStyle` 设置项，改成开关 `ttsStyleControl: boolean`（默认开）**。开关只在选中 MiMo 时显示（`ttsModelProvider(...) === 'mimo'`），其它模型下整行隐藏且开关值不参与任何逻辑。
2. **提示词只在「开关打开 + 模型是 MiMo」时追加一段「配音的语气」**（`CatalogOptions.styleControl`）：给出 `[风格:…]` 的写法、可选词表（MiMo 文档的整体语调 / 基本与复合情绪 / 音色质感 / 人设腔调 / 方言）、以及「一轮最多一个、只影响配音、不要复述台词」的约束；「输出什么」的形状行相应变成 `[风格:…]<表情>[动作]台词`。开关关闭或非 MiMo 时这段完全不进 system prompt——千问的提示词与改动前逐字一致。
3. **输出契约**：模型把指令写在台词最前面，形如 `[风格:慵懒、语速稍慢]`。`parseLeadingTags` 认 `[风格:…]` / `[语气:…]` / `[style:…]`（冒号中英文均可，最长 120 字），剥出来放进 `LeadingTags.style`，正文（`rest`）里不留；`consumeLeadingTags` 对「开头像语气标签但还没闭合」的情况继续攒 buffer（语气标签可能很长，16 字的未闭合窗口不够），避免半截标签被念出来。
4. **流式通道**：`ReplyChunk` 增加 `{ type: 'style'; style: string }`，`streamReply` 在正文之前发一次（收尾再兜底一次），保证 Host 在合成第一个分句前就拿到这一轮的指令；`/interact` 的非流式路径也把 `ReplyAttempt.style` 带出来。
5. **合成接线**：Host 的 speak 管线用一层 `styledChunks()` 把 `style` 帧吃掉（**不下发客户端**——气泡/前端都不该知道它），存进本轮 `replyStyle`；`synthesize` 时把 `{ ...voiceOptions(), style: replyStyle }` 交给引擎，MiMo 引擎的 `mimoBody` 把它放成 `user` 消息。千问引擎忽略 `style`，缓存键也因为 style 为空而保持不变。
6. **历史留痕**：`recordAiTurn` 接受 `style`，`taggedReplyLine` 把它渲染成 `[风格:…]` 前缀（和表情/动作标签同一位置），模型下一轮能看到自己上次用的语气；气泡与 `done.text` 不含。
7. 调试：控制台 `tts.request` 的 body 里能直接看到这轮的 `messages[0]`（user 风格指令），不需要额外埋点。

## Alternatives Considered

### 备选方案 A：保留写死的一句 `ttsStyle`，再加几个预置语气下拉

- Pros: 实现最小，用户可预期。
- Cons: 语气是「此刻」的，预置选项要么太粗（只能选 8 种）要么让用户自己去想组合；而且等于把「怎么说话」的一部分决定权从模型手里拿回宿主，和项目准则相反。
- Rejected: 交给模型自己按情境挑，用户只需一个开关。

### 备选方案 B：让模型把风格标签写进 MiMo 的 assistant 内容（`(慵懒)` / `[耳语]` 音频标签）

- Pros: 少一次请求字段，标签与台词天然同步。
- Cons: 这些内联标签会被念出来/进气泡，必须再做一层清洗；而且千问路径也会看到这些标签，等于为了 MiMo 改动通用输出格式。
- Rejected: 用「领先标签 + 单独的 `user` 指令消息」，控制信号与台词彻底分离。

### 备选方案 C：每轮随机挑一句风格指令

- Pros: 零提示词改动。
- Cons: 随机语气与剧情无关，会出现「愤怒地道歉」「慵懒地报错」，比写死更像 bug。
- Rejected: 情境相关的语气只能由模型判断。

## Consequences

- 设置页「语音」卡片里 MiMo 下多一行「风格控制」开关（默认开），千问下不显示；`ttsStyle` 字段从配置里移除，老配置里的值被忽略（schema 版本不 bump，归一化直接丢弃未知字段）。
- MiMo 每轮多一个 `user` 消息；系统提示词在开启时多约 500 字（关闭时不增加）。千问的请求与提示词完全不变。
- 历史里 assistant 行会带 `[风格:…]` 前缀：好处是模型能延续语气，代价是历史文本略长（模型可据此模仿，但不会因此输出到气泡）。
- 缓存键仍含 style，因此同一句台词在不同语气下会各存一份音频（与 ADR-061 一致）。
- 模型偶尔不写标签或写错：不写就用默认语气（合法降级）；写错/未闭合时流式会多等一会儿，极端情况下这一轮不带风格，不会把控制信号念出来。
