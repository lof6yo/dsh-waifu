# ADR-050：标签分形——表情用尖括号、动作用方括号

- 状态：Accepted
- 日期：2026-11-07

## 背景

ADR-037 起，表演指令是「方括号 + 目录 id」，表情和动作共用一种外壳：`[blush][ShakeHead]`。
这在**模型侧**是可写的，但在**契约侧**是含混的：

- 外壳不携带种类，只能靠目录反查；一旦模型写两个同种（实测 `[Sway][Glance]` 4/24 次），
  解析器只能把它们当成「两个动作」交给播放器——第一个动作被第二个拦腰打断（抽搐）。
- 提示词里「表情最多一个、动作最多一个」必须靠文字约束，而示例本身是「两个方括号」，
  模型自然学会「两个方括号 = 合法」。
- 白盒调试时看不出模型「想写表情还是动作」，只能事后按目录猜。

## 决策

1. **外壳即语义**：表情写成 `<blush>`，动作写成 `[Nod]`。形状本身携带种类，解析不再依赖目录反查。
2. **目录按形状分节**：`## 你能做的表情（尖括号）` / `## 你能做的动作（方括号）`，每行释义也用对应外壳写（`- <blush>：…`、`- [Nod]：…`）。
3. **输出形状只有一种**：`<表情>[动作]台词`，两个都可省略。
4. **外壳只是意图，目录说了算**：`<Nod>`、`[blush]` 这类写错壳的仍按目录归位（老历史、模型手滑不至于静默失效）。
5. **契约由宿主收敛，不靠模型自觉**：`filterTags()` 把表情、动作各截到「最后一个」——多写的按后写的算，与互斥组同一套规则。宁可只演一个，也不要第二个把第一个打断。
6. **记忆行保持 `[记]`**：它是「一整行的元信息」不是表演指令，提示词里明确「这一行照旧用方括号的 `[记]` 开头」。
7. **半截标签照旧扣住**：`openTagStart()` 同时认 `[No` 与 `<blu`，流式期间不露半个标签；气泡兜底的正则同步认两种外壳。

## 取舍

- **不引入 JSON**：ADR-033 的首字延迟依赖「边流边解析」，JSON 必须等结构完整。
- **不改成 `[E:blush][M:Nod]`**：多两个字符、可读性更差，而 `<` `>` 在中文语境里几乎不会出现在台词正文。
- **不保留「两种壳都当动作」**：那等于没解决歧义；旧数据的兼容靠「目录归位」而不是「按壳归类」。
- **不加第四个槽位**（例如强度、时长）：一个表情 + 一个动作已经够演，槽位越多模型越容易乱写。

## 影响

- `src/ai.ts`：`TAG_ANY` / `TAG_HEAD` / `TAG_PARTIAL` 支持两种外壳；`resolveTag(word, style?)` 按外壳决定先查哪张表；`parseLeadingTags` / `stripInlineTags` / `takeInlineTags` / `openTagStart` 全部按外壳解析；`filterTags` 截到各一个。
- `src/timeline.ts`：`extractTags()` 同步认两种外壳（段内标签归本段、段尾顺延下一段）。
- `src/director.ts`：目录与输出形状改写；`taggedReplyLine()` 记录成 `<表情>[动作]台词`。
- `src/client/index.ts`：气泡兜底 `LEADING_TAG` 认两种外壳（防旧 Host / 半截流漏到脸上）。
- 测试：新增 6 条（两种外壳、写错壳仍归位、句中剥离、半截扣住、各截一个、流式合帧），golden 重算（system **1584 字 / `daa131a2`**、messages `49f45193`、payload `55b22958`），计 **272 tests**。
- 验收：`scripts/eval-in-character.mjs` 的「标签合规」判定改为「≤1 `<表情>` + ≤1 `[动作]` + id 在目录内 + 正文无残留标签」。
