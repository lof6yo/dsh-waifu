# ADR-021：基础动作组（点头 / 摇头 / 歪头 / 左右晃 / 上下跳）

- 状态：Accepted
- 日期：2026-11-05
- 关联：取代 ADR-020 的「只留 Idle」；spec §5/§6；`scripts/gen-jian-motions.mjs`；`src/client/index.ts`

## 背景

ADR-018/019 的两轮动作（状态 + 触摸 + 人设，共 17 组）观感始终不对：胸部/躯干
的反馈像被人推着晃，比鼠标跟随时的自然摆动还差。ADR-020 因此把动作集整体退回
只有 `Idle`，等待重新设计。

重新审视后确定两条结论：

1. 模型的躯干、胸、胯、头发、衣服参数**全是物理输出**（`ParamChestAngleX/Y` 权重
   100、`ParamBodyAngleX0/Y0/Z0` 30/50/80），手写曲线只能拿到残余权重，写多了就是
   「木偶被掰」的刚性感；
2. 真正自由、且能通过物理链带动全身的只有**头部三个角度 + 头部平移**（`ParamAngleX/Y/Z`、
   `ParamAnglePX/PY`，物理归一化 ±10），以及表情参数（眼/眉/嘴/腮/眼球）。

所以本轮不再做「受击反应」这类需要大幅躯干位移的动作，只做**头部 + 表情层面**
的基础动作，让身体自然跟随。

## 决策

新增 5 个动作组，`scripts/gen-jian-motions.mjs` 幂等生成，并写进
`assets/models/jian/简.model3.json` 的 `Motions`：

| 组名 | 文件 | 时长 | 设计 |
| --- | --- | --- | --- |
| `Nod` 点头 | `motions/nod.motion3.json` | 1.3s | 两次、先浅后深；侧倾比俯仰晚 0.1s 到位；收尾上抬 1.6° 过冲再刹车回落；点头时眼睑下压，抬起来前眨一次 |
| `ShakeHead` 摇头 | `motions/shake-head.motion3.json` | 1.4s | 三次左右，幅度 −8.4° → +8° → −6.2° → +4° 递减；侧倾与转头错帧；中段眨眼；眉毛压低、嘴角下拉 |
| `Tilt` 歪头 | `motions/tilt.motion3.json` | 1.8s | 慢起 0.3s 到 9.2°，停住约 0.6s，回正时反向过冲到 −1.2°；眼球上移、眉梢抬、腮微鼓 |
| `Sway` 左右晃 | `motions/sway.motion3.json` | 2.8s | 两个来回的正弦（`AngleZ` ±6.3、`AngleX` ±4.2 相位差 0.55、`AnglePX` ±2.4），头尾 12% 包络保证从静止起、回静止收；两次眨眼 |
| `Hop` 上下轻跳 | `motions/hop.motion3.json` | 1.1s | 蓄力下蹲 0.16s → 腾空抬下巴 → 落地缓冲回弹；嘴张开、腮鼓、起落各一次眯眼 |

**Hop 的位移在渲染层补**：模型没有可驱动的根位移参数（`ParamBodyAngleRX/RY/RZ`
分别是权重 100/70/10 的物理输出），纯动作只能做出「点头+表情」。因此
`src/client/index.ts` 在动作成功启动时，若组名是 `Hop`，给 canvas / touchbox overlay /
命中层同时加一段 0.62s 的抛物线 `translateY` + 起落 `scaleY`（`transform-origin: 50% 100%`），
只动渲染元素，不改 `pos` 与命中判定，播完复位。

默认事件映射随之接通（`src/presets/presets.jsonc` 与 `src/models.ts` 的
`DEFAULT_MOTION_MAP` / `DEFAULT_EVENT_BINDINGS` 一致）：

| 事件 | 动作组 |
| --- | --- |
| 空闲 | `Idle` |
| 思考 | `Tilt` |
| 等审批 | `Sway` |
| 出错 | `ShakeHead` |
| 完成 / 交付 | `Hop` |

触摸部位默认**不挂**动作（只出气泡），用户可在设置页按部位多选挂上这 5 个。

## 曲线制作要点（依据 Live2D 官方《提高动态质量》）

- **不要只动脸**：本模型的「身体跟随」由物理完成，头部角度一给，胸/腰/头发就通过
  摆锤链自然滞后跟随，这正是上一轮手写躯干曲线失败的原因。
- **错帧**：脸与身体、转头与侧倾不要同帧到位，否则像机器人。
- **后坐力 / 踩刹车**：想停下来的地方先过冲再回落（`Nod` 结束的 +1.6° 上抬、
  `Tilt` 回正的 −1.2° 反向）。
- **自然穿插**：转头/换视线时眨眼；表情要有眉毛参与的细微变化。
- **张弛**：同一动作里幅度递减（`Nod` 先浅后深、`ShakeHead` 三次递减）。
- **角色相符**：「简」是年轻女性角色，歪头/晃动这类可爱动作可以给足幅度
  （`Tilt` 9.2°、`Sway` 6.3°），但不要写成用力甩。

## 影响

- `简.model3.json` 的 `Motions` 由 1 组变 6 组；`gen-jian-motions.mjs` 的
  `EXPECTED_GROUPS` 与量纲白名单同步（新增 `ParamAnglePX/PY` ±10）。
- 设置页无需改动：动作组下拉本来就读 `.model3.json` 的 `Motions`。
- `Nod`/`ShakeHead`/`Tilt`/`Sway` 只驱动头部角度、平移与表情，不碰任何物理输出参数；
  `Hop` 额外依赖渲染层的位移补偿，属于客户端表现，不影响动作文件本身的可移植性。

## 备选方案

- **继续手写躯干/胸曲线**：已证伪（ADR-019 的冲量方案）。物理输出权重吃掉大部分值，
  写满也会被拉回，观感是刚性摆动。
- **改物理参数（降权重/调刚度）**：动的是模型自带 rig，会影响鼠标跟随时的全身观感，
  风险大于收益。
- **Hop 用 `ParamBodyAngleRY` 顶替位移**：权重 70（仅 30% 生效），且它不是竖直位移，
  试算后放弃，改用渲染层补偿。
