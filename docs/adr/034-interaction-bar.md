# ADR-034：模型上的交互条（静音 + 对话）

日期：2026-11-05
状态：已采纳

## 背景

桌宠的 AI 演绎只能由「戳部位 / 状态变化」触发，用户没法主动跟它说话；语音开关也只能进设置页关。
需要一个总在模型旁边的入口。

## 决策

在模型包围盒的**上方或下方**贴一条胶囊状交互条，从左到右：

1. **圆形静音按钮**：直接切设置里的 `ttsEnabled`（写回 `settings.jsonc`，其它端经 SSE 同步）；
   静音只影响语音，台词与口型之外的文字照常。
2. **胶囊对话输入框**：回车把这句话交给模型——人设（persona.md）+ 场景描述 + 最近历史，
   回复走与触摸同一套管线（气泡按句读显示、TTS 逐段播、口型跟随）。

设置项 `barPosition: 'top' | 'bottom'`（默认 `bottom`，设置页「显示 → 交互条」）。
新增 `ReplyContext.kind = 'chat'`：`buildSceneMessage()` 输出
「主人刚对你说「…」」并改用「回应主人这句话」的指令（其余场景仍是「即兴演一下这一刻的反应」）。

## 理由

- 复用 `/speak` 流式管线：一句用户输入自动获得气泡、语音、口型、历史记录，不需要新链路；
- 静音写设置而不是纯前端状态：刷新/换端后一致，用户不用再进设置页找；
- 位置做成设置项而不是自动判断：气泡在模型上方，交互条默认放下方，避免两者打架；
- 输入框 `maxLength = 200`，Host 侧再截 200，防止一次塞进超长 prompt。

## 后果

- 交互条占用模型上下约 32px 空间；模型贴屏幕底部且选「下方」时可能被视口裁掉（位置按包围盒算，不做避让）；
- 「全 AI 接管」与「仅触摸」开关对交互条不生效：用户主动说话永远走模型；
- 交互条上的指针事件停止冒泡，不会误触发拖拽/点击互动；
- 冷却（1.2s）对聊天同样生效：连按两次回车只发一句。
