# ADR-026：长状态取消多阶段固定台词，改由 AI 按节奏演绎

- 状态：Accepted
- 日期：2026-11-05

## 背景

`thinking` / `waiting` 原本有「多阶段固定台词」：入态一组，之后按 15s / 40s（思考）、
30s / 90s（等确认）再各推一组（`EVENT_STAGE_DELAYS`）。接上 AI 回复（ADR-025）后问题暴露：

- 阶段台词会**抢走** AI 那句：AI 出字比固定节奏慢，刚上屏就被下一阶段盖掉；
- 阶段台词是写死的，同一个状态反复出现时观感机械，用户明确反馈"取消多 phase 的固定台词触发"；
- 长状态恰恰是最该"活着"的时刻——想了 40 秒还在说"马上就好…"很出戏。

## 决策

1. **只保留入态台词**：事件绑定里 `lines` 收敛为一组（旧的二维数组取第一组，其余丢弃），
   设置页的事件卡片只剩一个台词 textarea。`EVENT_STAGE_DELAYS` 删除。
2. **长状态气泡常驻**：`thinking` / `waiting` 期间入态台词常驻气泡（不再 2.5s 自动隐藏）；
   瞬态气泡（触摸/短状态）到时后回落到常驻底稿。
3. **AI 演绎替换常驻台词**：入态台词先出，AI 那句到了就替换，并成为新的常驻底稿；
   直到出态或下一次替换。
4. **节奏可配，粒度到状态**：`thinking` / `waiting` 各自三个设置项（`settings.jsonc` 扁平键）：

   | 键 | 含义 | 默认 | 范围 |
   | --- | --- | --- | --- |
   | `thinkingAiDelay` / `waitingAiDelay` | 入态固定台词出现后，隔多久开始第一次演绎（秒） | 3 / 4 | 0–120 |
   | `thinkingAiInterval` / `waitingAiInterval` | 之后的演绎间隔（秒） | 20 / 30 | 5–600 |
   | `thinkingAiMax` / `waitingAiMax` | 每次入态最多演绎几次 | 3 / 3 | 1–10 |

   计时器只在长状态期间存在：出态立即 `clearTimeout`，空闲时零进程、零定时器。
5. **失败降级**：某次演绎失败/超时/返回空文本时保留当前文案，下一次间隔再试；
   尝试次数计入上限（避免模型不可用时无限重试）。
6. **「仅触摸」仍优先**：`aiTouchOnly` 开启时长状态完全不请求模型，只有入态台词。

## 后果

- 设置页事件卡片少了两块 textarea；旧存档里的多阶段台词在归一化时被裁掉（不可恢复，属于有意的行为变更）。
- AI 调用的次数上限由 `*AiMax` 明确约束，长时间等待不会无限烧 token。
- 演绎节奏与模型延迟无关：慢模型只是某次替换晚到，常驻台词兜底，不会出现空白气泡。
