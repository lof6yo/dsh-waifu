# ADR-052：气泡在一轮演绎期间不自动消失

- 状态：Accepted
- 日期：2026-11-07

## 背景

台词文字比声音早到（ADR-048 第五步：`clause` 帧一到就上屏，音频随后才合成播放）。而气泡的展示时长一直是「替换文案后 2.5 秒」（`BUBBLE_DISPLAY_MS`）。

于是出现一个自相矛盾的观感：一句话被切成 3 段，文字 1 秒内就全部到齐 → 2.5 秒后计时器把气泡收掉 → 此时第 2、3 段音频还在播 → 播完（`done`）又用完整台词重新显示一次。用户看到的就是「气泡偶尔消失，播完之后又出现」。

「偶尔」是因为只有多段、且合成慢的那几轮才会跨过 2.5 秒；单段短句不会。

## 决策

1. **气泡的展示时长从「整轮演完」起算，不从「一段文字到达」起算**。一轮之内只换文案、不收起。
2. 用 `bubbleHeld` 布尔表达「这一轮还开着」：`startTurn()` 开时按住、`finally` 里放开；放开时若气泡仍可见，重新起算 2.5 秒。
3. `showBubbleNow()` 只在未按住时安装隐藏计时器；`revealClausesUntil()` 因此天然不再与音频赛跑。
4. 不改 ADR-027 的「最长显示（秒）」兜底：那是防气泡永久常驻的保险，与「一段文案停多久」是两件事，仍然按「隐藏 → 可见」起算。
5. 不看音频进度做计时（不去听 `motionFinish`/`onended` 再决定要不要收）：音频结束事件在浏览器里不可靠（自动播放被拒、标签页休眠、解码失败都会吞掉），而「轮次结束」是客户端自己发起的请求，信号确定。

## 取舍

- **气泡会在长台词时挂得更久**：这是想要的——正在说话时气泡消失才是 bug。
- **两个隐藏计时器并存**（每轮 2.5 秒 + 全局最长 10 秒）：语义不同，前者是「说完停一会儿」，后者是「兜底别永远挂着」。
- **打断时气泡立刻换新**：`interrupt` 模式下新一轮会 `stopSpeaking()` 并重新按住，旧文案被新文案替换，不额外做过渡。

## 影响

- `src/client/index.ts`：新增 `bubbleHeld` 状态、`armBubbleHideTimer()`、`setBubbleHold()`；`showBubbleNow()` 改走计时器助手；`startTurn()` 在读请求前后按/放。
- 行为变化：多段演绎过程中气泡不再消失；单句场景与之前一致。
- 无 Host 改动，刷新页面即生效。
