# ADR-032：打断优先级（触摸互动 vs 状态事件）

## 背景

触摸与状态事件共用同一条「气泡 + 动作 + AI 演绎」通道，过去没有显式规则：

- 短状态先闪预置台词再被 AI 替换；长状态（思考 / 等审批）有常驻底稿，并按 ADR-026 的节奏反复演绎；
- 触摸会放自己的台词、表情与互动动作；

结果是**长状态期间点宠物「没反应」**：触摸台词刚上屏，长状态的 AI 演绎（或常驻底稿回落）立刻把它顶掉，
动作也会被状态动作（FORCE 优先级）盖住。用户希望「点一下就有回应」，但也不排除有人希望状态演绎优先。

## 决策

新增设置项 `interactionMode`（设置页「对白气泡」卡片最后一行「打断优先级」，默认 `touch-first`）：

| 取值 | 行为 |
| --- | --- |
| `touch-first`（触摸优先，默认） | 触摸立刻接管：停掉长状态的演绎计时与常驻底稿，窗口内（2.6s）不显示状态台词、不播状态动作、不发状态类 AI 请求；窗口结束后若长状态仍在，重新「入态」把演绎与底稿交还 |
| `mutual`（互相打断） | 触摸立刻接管（同上），但状态一变就立刻收回窗口、由新状态接管气泡与动作 |
| `event-first`（事件优先） | 触摸不打断长状态演绎：只播自己的表情/动作，气泡与 AI 演绎仍归状态事件（旧行为） |

实现要点：

- 客户端只有一处「保持窗口」状态 `tapHoldUntil`（`TAP_INTERACTION_HOLD_MS = 2600`），
  `beginTapHold()` 在命中部位后进入窗口、清掉 `longAiTimers` 与 `bubbleStickyText`，并挂一个到期回调交还控制权；
- `applyState()` 里 `mutual` 先 `clearTapHold()`；`touch-first` 且窗口内时，长状态只记 `longState` 不显示底稿、
  短状态既不显示台词也不发状态请求，两者都跳过 `playState()`（不抢互动动作）；
- `requestAiReply()` 对 `kind === 'state'` 在非 `event-first` 且窗口内直接返回（触摸的 AI 台词优先）；
- 保持窗口是**纯客户端计时**（一个 `setTimeout`），没有新增轮询；组件销毁时随 `pushCleanup` 清理。

## 后果

- 长状态期间点宠物一定有即时反应（台词 + 表情 + 动作），状态演绎最多晚 2.6s 继续；
- `event-first` 保留旧观感，供「状态更重要」的场景使用；
- 触摸与状态在 2.6s 内的竞态被一条明确规则收敛，不再出现「AI 台词把触摸台词顶掉」的随机感；
- 已知局限：窗口内多次触摸只延续同一窗口（不做叠加计数），连续快速点击时演绎会持续被推迟。
