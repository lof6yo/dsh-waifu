# ADR-039：历史注入改短句、DSH 事件文案可配置

- 状态：已采纳（2026-11-06）
- 相关：ADR-030（历史注入）、ADR-037（全 AI 驱动）

## 背景

ADR-030 把「当时发出去的那条用户消息」原样记进历史。ADR-037 之后那条消息是一个完整场景句：

```
（现在是 11月6日 周四 16:22。主人轻碰你的「脸」，按了约 0.2 秒。）你就是这个人。这就是你此刻真实遇到的事，直接给出你的反应。
```

历史注入默认 20 轮 = 40 条消息，同一段「现在是…／你就是这个人…」要重复 20 遍。
内容上 80% 是重复的框架文字，真正的信息只有「谁做了什么」几个字；token 上它把
system 之外的最大一块预算吃在无信息量的模板上，还稀释了模型对时间戳的注意力。

同时，DSH 事件的描述（「主人让你跑命令，你刚按下回车」…）写死在 `src/ai.ts` 的
`EVENT_SCENES` 里。这是**角色人格的一部分**：不同的桌宠该用不同的口吻描述「主人在干活」，
而它此前只有内置一种说法，用户能改的只有开关。

## 决策

### 1. 历史只存最短事实

`historySceneText(context, eventTexts)` 生成一行式短句，写历史时用它，当前请求仍用完整场景句
（`buildSceneMessage`）——模型这一轮需要「现在是几点 + 发生了什么 + 该怎么回」，
往后回看只需要「谁做了什么」：

| 触发 | 当前请求（完整） | 历史（紧凑） |
| --- | --- | --- |
| 触摸 | 主人轻碰你的「脸」，按了约 0.2 秒 | 主人轻碰「脸」（1.2s 才带秒数） |
| 对话 | 主人刚对你说「…」 | 主人说「…」（截 40 字） |
| 事件 | 眼下主人让你跑命令，你刚按下回车 | 主人让你跑命令，你刚按下回车 |
| 合并 | 这期间还发生了：…；…。 | 主句（另有 N 件事） |
| 静默 | 有一阵子没人理你，也没发生什么事 | 一阵子没动静 |

历史消息本身仍由 `historyMessages()` 加 `[HH:MM]` 前缀，模型据此判断多久以前。

### 2. 事件文案可在设置页覆写

- 内置文案搬进 `src/defaults.ts` 的 `DEFAULT_EVENT_TEXTS`（客户端也要用它做输入框 placeholder，
  不能留在只会被 Host 加载的 `ai.ts` 里）。
- 新设置 `eventTexts: Record<事件键, string>`：空 = 用内置；归一化只保留 `TRIGGER_EVENTS`
  里的键、压空白、截 `EVENT_TEXT_MAX = 60` 字；空串等于删除覆写。
- `eventSceneText(event, texts)` 三级回落：用户文案 → 内置文案 → `发生了「<键>」这件事`。
- 设置页「触发场景」每个事件：开关 + 一个文本框（placeholder 显示内置文案，`title` 也带一份）。
- 写入走 `applyOps` 的二层路径 `['eventTexts', '<事件键>']`，与 `eventTriggers` 同机制。

## 后果

- 历史注入的 token 占用明显下降（一行式短句 vs 整段场景句），20 轮时尤其明显。
- 事件文案成为人格的一部分，可随人设定制；代价是设置页「触发场景」从纯开关网格变成
  开关 + 输入框，区块变高。
- `eventTexts` 不进 cordis schema（和 `eventTriggers` 一样由 Host 侧默认值补齐），
  `Config({})` 里没有该键——一致性测试里单独断言形状。
- 历史是内存态（重启清空），旧历史不受格式变更影响。
