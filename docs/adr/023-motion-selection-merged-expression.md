# ADR-023：动作组与表情合并为同一套「动作 / 表情」混选

- 状态：Accepted
- 日期：2026-11-05
- 取代：ADR-022 的「基础表情 + 连续参数强度滑杆 + 卡片里单独的表情下拉」部分

## 背景

ADR-022 把表情做成两处入口：设置页「表情」分组（基础表情 + 4 个连续参数强度滑杆）与事件/部位卡片里各自的「表情」下拉。实际用下来：

- 连续参数（`AnimeAngry` / `AnimeAngry2` / `Anime_Cry` / `Anime_Eye`）在实机上观感几乎看不出来，滑杆调完没有可感知差异；
- 「基础表情」常驻这一层也没有使用场景——表情本来就是「被某件事触发」的；
- 事件/部位卡片里「动作组」和「表情」两行并排，长的像同一个东西，实际却分两套交互（一个多选下拉、一个原生 select）。

用户要的是：事件绑定与触摸部位各只有**一个**「动作 / 表情」选择器，列表里分组显示「动作」「表情」，绑定一个动作（可不选）+ 一个表情（可不选），同时触发。

## 决策

1. **一套数据**：`motions: string[]` 继续承载这个槽位，里面混存两类名字——动作组名与表情 id
   （`blush` / `angry` / `star` …）。区分方式是查 `EXPRESSIONS` 注册表（`isExpressionId`）。
2. **每个槽位最多 1 个动作组 + 1 个表情**：`splitMotionSelection()` 拆解、`joinMotionSelection()`
   拼回（顺序固定：动作组在前），`normalizeMotionSelection()` 负责去重与裁剪。
3. **旧字段并入**：`EventBinding.expression` / `TouchPart.expression` 删除；读取旧文件时把该字段
   的值并进 `motions`，未知表情被丢弃（`normalizeExpressionId` 回退 `none`）。
4. **设置页只留一个下拉**：`ThemeMultiSelect` 支持 `group` 与 `singlePerGroup`，动作组与表情各
   成一组、组内单选；点击同组另一项即替换。
5. **删掉连续参数与基础表情**：`PetSettings` 去掉 `expression` / `exprAngry` / `exprAngry2` /
   `exprCry` / `exprEye`，设置文件版本升到 4；`EXPRESSION_LEVELS` 注册表一并删除。
6. **优先级不变**：调试面板预览 > 触摸临时表情（2.2s）> 当前事件绑定里的表情。

## 为什么不做成两套字段

两套字段意味着两套归一化、两套 UI 分支、两份迁移逻辑，而它们的语义完全一样——都是「这个槽位
要角色演出什么」。混进一个数组后，默认值、预设、运行时解析都只有一个入口；设置页也只需要维护
一个控件。

## 后果

- 事件绑定 / 触摸部位卡片各少一行；设置页少一个分组。
- 升级时旧配置里的表情不会丢：并入 `motions` 后照样生效，只是位置从独立字段变成列表里的一项。
- 「多个动作组候选、随机选一个」的能力取消：一个槽位就是确定的动作组 + 表情，行为更可预期。
- 表情仍是常驻参数（ADR-022 的每帧覆写 + 淡入淡出不变），只是触发入口收敛。
