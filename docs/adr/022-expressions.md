# ADR-022：表情系统（参数开关 + 连续参数）

- 状态：Accepted
- 日期：2026-11-05
- 取代：—

## 背景

「简」的模型里有一整套表情资源，插件此前完全没用到：

- 布尔开关（`ParamSwitch1`–`9`、`ParamSwitch21`）：脸黑 / 脸红 / 血 / 生气 / 星星眼 / 白眼 /
  泪花 / 爱心眼 / 眼泪 / 高光消失；
- 连续参数：`AnimeAngry`（生气抖动）、`AnimeAngry2`（生气冒火）、`Anime_Cry`（眼泪流动）、
  `Anime_Eye`（转圈眼）；
- `ParamSwitch10/11`（左右手）是姿势开关，不是表情，不纳入。

这些参数**不是动作**：`model3.json` 没有声明 `Expressions`，所以不能靠 `model.expression()`
播放；写进 motion3 又只能一次性扫过、无法常驻。用户要的是「事件/触摸触发后一直保持，直到下一次变化」。

## 决策

1. **每帧覆写参数**：包装 `InternalModel.update`，在动作与物理生效前把「当前表情」的开关写成
   1、其余开关写成 0；连续参数按设置里的强度写 0–1。动作不会驱动这些参数，物理也不输出它们，
   因此覆写不会被覆盖。
2. **淡入淡出**：每个参数维护一个混合值，按 `EXPRESSION_FADE_MS`（280ms）向目标线性逼近，
   避免开关式突变。目标变化只在「要求切换」时发生，其余帧保持，不会抖动。
3. **三层优先级**：触摸临时表情（`EXPRESSION_TEMP_MS` = 2200ms）> 当前事件绑定表情 > 基础表情
   （`settings.expression`）。触摸表情到点自动回落到事件/基础表情，不需要额外清理。
4. **触发方式与动作一致**：事件绑定卡片里每个事件可选一个表情，触摸部位卡片里也可选一个表情；
   设置页「表情」分组另有「基础表情」下拉与 4 个强度滑杆。
5. **连续参数走设置 + SSE**：滑杆写入 `settings.jsonc`（`exprAngry` / `exprAngry2` / `exprCry` /
   `exprEye`，0–100），经既有 SSE 推送到宠物半边实时生效——拖动即看到变化，不需要保存按钮。
   写入做了 90ms 防抖，避免拖拽把文件写满。
6. **默认值**：出错→`angry`、完成→`star`、交付→`heart`；其余事件与部位默认不指定表情
   （沿用基础表情）。

## 为什么不把表情做成动作

- 表情是**常驻状态**，动作是**一次性时间轴**；用动作表达常驻状态只能靠 `Loop=true` 的空转，
  会和状态动作抢 `MotionPriority`，还会被 `motionFinish` 逻辑当成「播完了」恢复 Idle。
- 模型本身没有 `Expressions` 定义，Cubism 的 expression 通道不可用，只能直接写参数。

## 后果

- 表情与动作可以叠加（例如「生气」+ `ShakeHead`），互不干扰。
- 同一时刻只能有一个布尔表情（后写覆盖），`AnimeAngry` 这类连续参数可与其叠加。
- 若后续模型提供 `Expressions`，可在 `EXPRESSIONS` 注册表里增加 `expressionId` 字段优先走原生通道，
  现有开关注册表保持兼容。
