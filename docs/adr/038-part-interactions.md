# ADR-038：部位自定义交互（名字由用户起，触发条件可选）

- 状态：接受（2026-11-06）
- 相关：ADR-037（全 AI 驱动，删掉固定台词与手动动作映射）、ADR-031（AI 接管）

## 背景

ADR-037 之后，触摸只剩「部位名 + 按压时长」交给模型：客户端固定按 250ms / 900ms 把按压分成
轻碰 / 戳戳 / 抚摸三档（`src/defaults.ts:222 touchKindOf()`）。这有三处不合适：

1. 阈值写死在代码里，用户改不了；
2. 「抚摸」要求按住 ≥900ms 且抬手位移 ≤12px，实际几乎摸不出来（一滑动就变成拖动宠物）；
3. 三档之外没有表达空间——用户想区分「捏脸」「弹一下」「掐一把」只能改代码。

## 决策

把「什么动作」交回给用户：**每个触摸部位可以自定义若干条交互**，每条 = 名字 + 触发条件。

```jsonc
{
  "id": "face", "name": "脸", "boxes": [ ... ],
  "interactions": [
    { "id": "i1", "name": "抚摸", "trigger": "hold", "holdMs": 3000 },
    { "id": "i2", "name": "捏脸", "trigger": "tap" },
    { "id": "i3", "name": "戳戳", "trigger": "double" }
  ]
}
```

- **名字**：用户自由填写（≤20 字），**原样**进场景句——「主人抚摸你的「脸」」。
  模型按字面理解语义，system prompt 明确要求「这是主人自己起的交互名，不要当成动作 id，也不要复述」。
- **触发条件**：
  - `tap` 单击（≤300ms 内没有第二下）；
  - `double` 双击（两次点击间隔 <300ms，同一部位）；
  - `hold` 停留 = **鼠标悬停**在该部位 box 内 ≥ `holdMs`（默认 3000ms，可调 300–10000ms），不需要按下；
    悬停期间在 box 内移动不影响计时；移出 box / 按下（要点击或拖动）立即清零重计；同一趟悬停只触发一次，
    移出再回来重新计时（2026-11-06 修订，原实现是「按住 ≥holdMs」，实际几乎按不出来）。
- **判定顺序**（`src/models.ts`）：悬停由 `beginHover` 单独负责（多个 hold 取 holdMs 最短那条）；
  按压路径走 `pickTapInteraction()` 只挑单击/双击，hold 不再参与按压判定。
- **不再兜底（2026-11-06 修订）**：部位没有 `interactions`、或没有匹配当前触发条件的交互 → **不触发**，
  点了没有任何反应（气泡、动作、AI 全都不发生）。理由：三档时长兜底等于把「什么算互动」又写死在代码里，
  用户既然能自己定义交互，就不该有一条他看不见的隐藏行为。
  内置 preset 的部位自带两条示例交互（「轻碰」单击、「抚摸」停留 3s），保证新装开箱可用。
- **交互数上限** 8 条/部位、名称 ≤20 字，设置页同步限制。

## 客户端实现要点（`src/client/index.ts`）

- `pointerup` 位移 ≤12px 才算触摸（>12px 是拖动宠物），与 ADR-032 一致。
- 定义过 `double` 的部位：第一次点击压 300ms（`DOUBLE_TAP_MS`）等第二下；
  期间点到别的部位就把欠着的单击立刻补发（`pendingDoublePart.flush`），不会吞点击。
- 没定义 `double` 的部位立即结算，保证跟手。
- 悬停（`beginHover`）：命中 div 挂 `pointerenter/pointerleave`；到时触发的请求带
  `{ interaction, hover: true }`，场景句用悬停措辞「主人抚摸你的「脸」（鼠标一直停在那里）」，
  历史短句 `主人抚摸「脸」`——**不带秒数**，否则模型把「停留」读成「戳了 N 秒」（用户实测踩坑）。
- 交互名经由 `TriggerBody.interaction` → `TriggerInput.interaction`（routes 白名单）→
  `ReplyContext.interaction`（index 透传）进 `buildSceneMessage`；此前 routes/index 转发缺失，
  模型只能看到兜底的「戳了戳」——这是「干嘛戳我脸那么久」的根因。

## 后果

- 触摸语义完全可配，且全部经由模型理解，不新增任何「动作→台词」的映射表。
- 单击在「配了双击」的部位会有 300ms 延迟——这是识别双击的必要代价，只在需要的部位付出。
- 「抚摸」不再依赖代码里的 900ms 阈值；用户想要「按 3 秒才算抚摸」就写 3000ms。


## 修订二（2026-11-06）：停留 = 悬停，交互名修通

1. **`hold` 从按压改成悬停**：按住 3s 实际按不出来（位移超 12px 就成拖动）；用户定义的语义是
   「鼠标放在 box 里就算」。悬停在 box 内移动不重置，移出/按下重置，单趟只触发一次。
2. **交互名链路修通**：`routes.parseTriggerInput` 白名单缺 `interaction`、`index.beginAiTurn` 未透传，
   导致场景句恒用 `tapKind` 兜底「戳了戳」。两端补上（`hover` 标记后来随修订四一并删除）。
3. **措辞**：场景句不区分触发方式、也不带时长（见修订四）——模型才不会把
   「停留」理解成「戳了很久」。
4. **按压路径只挑 tap/double**：`pickTapInteraction()` 取代按压判定里的 `pickInteraction`，
   hold 交互不再能被「长按」触发（避免同一交互两条触发路径）。
5. **内建三档彻底删除**（用户明确要求「有定义才有触发，不要兜底」）：`touchKindOf`/`touchKindLabel`/
   `TAP_KIND_SCENES`/`TapKind`/`tapKind` 字段全删。场景句没有交互名时只说「主人碰了你的「脸」」，
   不再编造「戳了戳」「温柔地抚摸」这类未定义的动词。

## 修订三（2026-11-06）：悬停场景句与指令措辞

- 「停留」由悬停触发时，场景句不再附带「（鼠标一直停在那里）」——只写「主人<交互名>你的「<部位>」」，实现细节（鼠标/悬停）不进场景。
- 场景末尾指令统一为「按你的人设回应。」——所有触发场景（触摸/对话/事件/静默）共用一句，不再说「演」，也不按场景分叉。
- 触摸场景句统一为「主人「<交互名>」了你的「<部位>」」：单击/双击/停留只是**触发方式**，不进场景句，「互动」按抽象概念处理；请求体随之不再携带 `hover`/`durationMs`，`ReplyContext` 与历史短句同步（历史为「主人「<交互名>」了「<部位>」」）。`pickInteraction(part, durationMs, clickCount)` 随之删除，按压只经 `pickTapInteraction`（单击/双击），停留由悬停计时器独立负责。

## 修订四（2026-11-06）：内置 preset 的示例交互改成按手感命名的三条

- 「简」preset 的部位不再只给「轻碰 / 抚摸」两条占位交互，改为按各部位实际手感命名的三条：
  单击 / 双击 / 悬停 3s（例：脸=捏 / 亲 / 抚摸，头发=梳 / 抓住 / 抚摸，手=牵住 / 舔）。
  新装用户开箱就有一套能直接触发、语义明确的交互，不必先自己命名。
- 这条只改 `src/presets/presets.jsonc` 的默认数据，不改机制（ADR-038 的交互模型与触发路径不变）。
