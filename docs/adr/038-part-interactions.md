# ADR-038：部位自定义交互（名字由用户起，触发条件可选）

- 状态：接受（2026-11-06）
- 相关：ADR-037（全 AI 驱动，删掉固定台词与手动动作映射）、ADR-031（AI 接管）

## 背景

ADR-037 之后，触摸只剩「部位名 + 按压时长」交给模型：客户端固定按 250ms / 900ms 把按压分成
轻碰 / 戳戳 / 抚摸三档（`src/defaults.ts:222 touchKindOf()`）。这有三处不合适：

1. 阈值写死在代码里，用户改不了；
2. 「抚摸」要求按住 ≥900ms 且抬手位移 ≤12px，实际几乎摸不出来（一滑动就变成拖动宠物）；
3. 三档之外没有表达空间——用户想区分「捏脸」「弹一下」「掐一把」只能改代码。

## 决策

把「什么动作」交回给用户：**每个触摸部位可以自定义若干条交互**，每条 = 名字 + 触发条件。

```jsonc
{
  "id": "face", "name": "脸", "boxes": [ ... ],
  "interactions": [
    { "id": "i1", "name": "抚摸", "trigger": "hold", "holdMs": 3000 },
    { "id": "i2", "name": "捏脸", "trigger": "tap" },
    { "id": "i3", "name": "戳戳", "trigger": "double" }
  ]
}
```

- **名字**：用户自由填写（≤20 字），**原样**进场景句——「主人抚摸你的「脸」，按了约 3.2 秒」。
  模型按字面理解语义，system prompt 明确要求「这是主人自己起的交互名，不要当成动作 id，也不要复述」。
- **触发条件**：
  - `tap` 单击（≤300ms 内没有第二下）；
  - `double` 双击（两次点击间隔 <300ms，同一部位）；
  - `hold` 停留（按住 ≥ `holdMs`，默认 3000ms，可调 300–10000ms）。
- **判定顺序**（`src/models.ts: pickInteraction()`）：停留 → 双击 → 单击；停留取「时长达标里最长的那条」。
- **不再兜底（2026-11-06 修订）**：部位没有 `interactions`、或没有匹配当前触发条件的交互 → **不触发**，
  点了没有任何反应（气泡、动作、AI 全都不发生）。理由：三档时长兜底等于把「什么算互动」又写死在代码里，
  用户既然能自己定义交互，就不该有一条他看不见的隐藏行为。
  内置 preset 的部位自带两条示例交互（「轻碰」单击、「抚摸」停留 3s），保证新装开箱可用。
- **交互数上限** 8 条/部位、名称 ≤20 字，设置页同步限制。

## 客户端实现要点（`src/client/index.ts`）

- `pointerup` 位移 ≤12px 才算触摸（>12px 是拖动宠物），与 ADR-032 一致。
- 定义过 `double` 的部位：第一次点击压 300ms（`DOUBLE_TAP_MS`）等第二下；
  期间点到别的部位就把欠着的单击立刻补发（`pendingDoublePart.flush`），不会吞点击。
- 没定义 `double` 的部位、以及命中 `hold` 的情况都立即结算，保证跟手。

## 后果

- 触摸语义完全可配，且全部经由模型理解，不新增任何「动作→台词」的映射表。
- 单击在「配了双击」的部位会有 300ms 延迟——这是识别双击的必要代价，只在需要的部位付出。
- 「抚摸」不再依赖代码里的 900ms 阈值；用户想要「按 3 秒才算抚摸」就写 3000ms。
