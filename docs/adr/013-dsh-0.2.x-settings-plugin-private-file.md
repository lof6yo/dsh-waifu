# ADR-013：适配 DSH 0.2.x 的 settings 服务（改为插件私有设置文件）

- 状态：Accepted
- 日期：2026-11-04
- 关联：ADR-007（自定义人设走插件私有 JSONC）、ADR-006（SSE 推送）、ADR-012（0.1.5-rc.3 适配）

## 背景

插件原先按 DSH 0.1.5 的 `ctx.settings` API 实现：

- `ctx.settings.register(namespace, Schema, { base })` 注册设置 namespace；
- `ctx.settings.get(namespace)` 读取三层解析值；
- 设置面板经插件自身 HTTP API 调 `ctx.settings.mutate(ns, ops)` 写 `$DSH_HOME/settings.yaml` 用户层。

本机运行的是 DSH Desktop 0.2.1-rc.5。0.2.x 的 `ctx.settings`（`SettingsForms`）语义已变：

- 不再有 `register` / `get`；它是「插件 Config schema → 设置页表单」的投影（`describe` / `update` / `replace` / `mutate` / `configure`），
- 表单值来自 Loader 条目（profile patch），写入经 `configEditor.edit` 走正常 Loader 重应用路径（`applies: 'live'`），
- 也就是说：一次设置写入 = **整个插件条目重载**（fiber 重建、HTTP 路由重注册、SSE 连接断开重连）。

实测插件加载报错：`TypeError: ctx.settings.register is not a function`，插件无法激活。

若继续把热设置（开关 / 尺寸滑杆 / 帧率 / 模型选择）放进 `ctx.settings`，每次拖尺寸滑杆都会整插件重载，宠物闪烁 + SSE 重连 3s，不可接受。

## 决策

1. 热设置迁移到**插件私有文件** `$DSH_HOME/live2d-pet/settings.jsonc`（JSONC），由 `src/settings-store.ts` 管理：内存快照、同步写回、经 SSE 推送变化。与 personas / custom-models / touch-parts 的「插件私有 JSONC」模式一致（ADR-007）。
2. `Config` schema 保留，作为 base/default 层（cordis.patch.yml 的 `config` 注入）；用户改动不再写 profile patch，避免触发整插件重载。
3. 用 `ctx.settings.configure({ auto: false })` 隐藏 0.2.x 自动生成的 Config 表单页，避免与插件自带「桌宠配置」页重复且行为不一致（自动表单写入会重载插件）。
4. 设置读写 API `/api/live2d-pet/settings` 的 wire 形状保持不变（`{value, writable}` + `{ops}`），实现改为操作 settings store；设置页无需大改。
5. 旧 `settings.yaml` 中的 `customModels` 迁移逻辑保留（一次性写入 custom-models.jsonc）。

## 后果

- 设置**即时生效**，不触发插件重载，SSE 不中断。
- 设置文件是插件私有的，用户可直接编辑 JSONC；损坏时沿用上一份好结果并在设置页提示（与其他私有文件一致）。
- 与 DSH 官方「工具设置页表单」解耦：插件自定义设置页继续自绘，未来 DSH 若把第三方设置页/表单能力补齐，可再评估回到 `ctx.settings`。
- 文档（spec §2/§9）同步声明：设置持久化位置从 `settings.yaml` 改为 `$DSH_HOME/live2d-pet/settings.jsonc`。
