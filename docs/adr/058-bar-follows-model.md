# ADR-058：交互条随模型移动，取消水平视口夹取

日期：2026-11-09
状态：已采纳

## 背景

交互条（ADR-034）原先水平方向「按包围盒居中、再夹取到视口内」，保证窄窗口下条不会跑到屏幕外。
但这套夹取在手机上失效：`dsh-web-mobile` 在手机浏览器里打开后，模型画布按 `size=240`、`canvasPadX/Y=125%/50%` 计算约 832×704 CSS px，远宽于手机视口（约 360–400px）；交互条自身约 226px 宽，留给 `left` 的夹取范围只有 `viewportW − 16 − barW ≈ 110–140px`。
于是角色还能在整屏范围内拖动、交互条却很快被钉在屏幕右（左）边缘不动，出现「角色和互动条的可移动区域不一致」的观感；垂直方向没有夹取，也会被横向钉住放大成「整条卡住」。

## 决策

交互条水平位置只由模型包围盒决定（包围盒顶部中心 − 条宽 / 2），**不再夹取到视口**；它和模型一样可以随角色拖到屏幕边缘、允许部分移出视口。
`barOffset` 仍然只控制吸附侧的垂直偏移；`barPosition: 'hidden'` 与自动隐藏（ADR-053）逻辑不变。
气泡（ADR-057）本来就按包围盒居中、没有视口夹取，这次让交互条与它、也与模型的可移动区域对齐。

## 备选方案

- **保留夹取，同时限制角色可移动范围使条始终完整可见**：手机上条几乎占满屏宽，角色中心被压到约 110px 的活动范围，牺牲太大，否决。
- **仅在宽视口（画布完整放得下）时夹取，窄视口放开**：行为随窗口宽度突变，且桌面端拖到屏幕边缘同样会出现「条停、角色继续」，只是不明显；统一放开更可预期，否决。
- **窄屏时把条缩窄（输入框自适应变短）**：能让夹取范围大一点，但边缘仍会钉住，且输入可用性下降，否决。

## 后果

- 角色贴屏幕边缘时，交互条可能有一部分（极端时约一半）在屏幕外；这是「和角色一起移动」的预期行为，条仍可点击可见部分，且无操作会自动收起（ADR-053）。
- 桌面端行为基本不变：视口远宽于条，夹取原本就几乎不触发。
- 交互条不再有独立的水平定位约束，相关代码与 `layerRect` 使用减少；后续若要做「贴边时自动改到模型另一侧」需要单独设计。
