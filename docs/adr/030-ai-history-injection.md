# ADR-030：AI 演绎注入最近对话历史

- 状态：Accepted（2026-11-05）
- 相关：ADR-025（AI 回复）、ADR-026（长状态演绎节奏）

## 背景

AI 台词此前是「无状态」的：每次请求只带人设 + 这一次发生了什么（触摸了哪里 / 当前状态 + 参考台词）。
结果是同一段对话里反复出现同样的反应——被连戳三次脸，三次都是「别戳啦」，模型不知道上一条自己刚说过什么，
也接不住「刚才不是说不许摸吗」这类前后呼应。

## 决策

1. **Host 侧维护一份最近对话环形缓冲**（`AiHistoryEntry{role:'user'|'assistant', text}`），只存内存：
   - `user` = 我们发过去的情景描述（`buildSceneMessage(context)` 的原样文本）；
   - `assistant` = 模型当时真正上屏的台词（不是失败重试的原文本）。
   - 只记录成功的往来：失败 / 超时 / 空回复不入历史，避免把错误上下文喂给下一次。
2. **注入条数可配**：设置项 `aiHistoryCount`（0–50，默认 10），放在设置页「AI 回复」分组；0 = 完全不注入。
   归一化与设置页输入共用 `normalizeHistoryCount()`（`src/defaults.ts`），Host 归一化与界面夹取不会分叉。
3. **注入方式**：取最近 `aiHistoryCount` 条，**丢掉开头没有提问的 assistant 条目**（模型不喜欢以 assistant 开头的上下文），
   再拼到当前情景之前：`[history…, 当前情景]`。system prompt 不变（人设 + 输出要求）。
4. **缓存上限与注入上限解耦**：缓冲最多保留 50 条（`AI_HISTORY_MAX_ENTRIES`），注入多少由设置决定——
   用户把条数调大时不用重跑历史，调小也不会丢已发生的对话。
5. 连通性自检（`/ai-check`）**不读写历史**：它是一次性探针，不该污染对话上下文。

## 后果

- 连续触摸/状态流转时语气有延续性，模型能「顺着刚才的话往下说」，重复台词明显减少。
- token 成本与延迟随 `aiHistoryCount` 线性增长；默认 10 条约等于一次多轮短对话，代价可接受；设为 0 可完全恢复旧行为。
- 历史只存在内存：dsh-web 重启后清空（与「重启即新会话」的直觉一致，也避免把旧上下文写进磁盘）。
- 失败重试（关推理重试）只在成功那一次写历史，不会出现「同一句被记两遍」。

## 修订（2026-11-05，同轮）

第一版把**整段情景文本**（含「你下意识想说的是『…』」）写进历史，问题有两个：

1. 参考台词并没有上屏，进了历史就等于告诉模型「这（预置台词）是我说过的」，越聊越容易复读预置对白；
2. 兜底失败的预置台词不进历史，参考台词却进了，历史与真实气泡内容不一致。

改为：**历史只记真实发生的事**。`buildSceneMessage(context, { forHistory: true })` 去掉参考台词那半句，
当前请求仍完整带 hint（提示照旧有用），落历史的是干净版场景描述。
