# ADR-031：全 AI 接管（不显示固定对白）

## 背景

ADR-025/026 的默认节奏是「预置台词先出，AI 台词到了再替换」：短状态先闪一句固定台词，
长状态（思考 / 等审批）先显示入态台词当常驻底稿，之后再按「延迟 / 间隔 / 上限」让模型演绎。
这套折中在模型不可用或慢的时候很好看（不会空窗），但用户想要另一种观感：**固定对白一句都不要，
人物说什么完全由模型决定**（人设 + 场景描述 + 注入历史）。

## 决策

新增设置项 `aiTakeover`（设置页「AI 回复」→「全 AI 接管」，默认关）。打开且 `aiEnabled` 时：

1. **触摸**：部位预置台词既不显示、也不作为 hint 传给模型 —— 完全交给 persona + 场景 + 历史。
2. **短状态**：不显示入态台词，气泡先清空，只等模型那句；模型失败/超时则保持无气泡，
   **不回落**到固定台词（接管模式的定义就是「没有兜底台词」）。
3. **长状态**（思考 / 等审批）：不显示入态台词（也不留常驻底稿）；「延迟」失效——入态立刻请求。
   「间隔 / 上限」仍生效，用来在同一次长状态里隔一段时间再补一句。
4. 设置页在接管开启时把「思考节奏 / 等确认节奏」里的**延迟**输入框置灰，避免让人以为还能调；
   间隔与上限保持可编辑。
5. 与「仅触摸」共用 `aiEnabled` 前提：仅触摸 + 接管 = 状态完全不说话，只在被摸时由模型开口。

## 为什么不在 Host 侧做

接管改变的是「气泡怎么显示、什么时候请求」，全是宠物半边的渲染逻辑；Host 只管发一次请求。
放客户端意味着改完刷新即生效，Host 只会因为新增配置键（`normalizeSettings` 丢弃未知键）需要重启。

## 后果

- 接管开启 + 模型不可用时，宠物会**完全没有台词**（这是预期行为，不是 bug）；排查用
  `GET /api/dsh-waifu/ai-debug` 看最近一次载荷与失败原因（`/interact` 也会回 `no-reply: <原因>`）。
- 预置台词仍然保留在 `settings.jsonc` / `presets.jsonc` 里，关掉接管即恢复原行为。
- `aiTakeover` 是 Host schema 新键：旧 Host 进程不认这个键，设置页写入会被丢弃，需要重启 dsh-web。
