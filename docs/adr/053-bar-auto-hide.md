# ADR-053：交互条无操作后自动隐藏

日期：2026-11-09
状态：已采纳

## 背景

交互条（ADR-034）常驻在模型包围盒上方或下方，占一条胶囊的空间。大多数时候用户只是看着角色、并不打算说话，交互条却一直挡在那里——模型贴边或尺寸较小时还会压住模型/界面。需要「不用时让开、要用时出现」的轻量交互，而不是让用户每次进设置页关掉再打开。

## 决策

- 新增设置 `barAutoHideSec`（秒，0–3600，**默认 10**，0 = 一直显示），放在设置页「AI 驱动 → 触发」卡片内、交互条行之后（数值框步进 1，回车/失焦即保存，与同组数值项一致）。
- 「有操作」的判定：指针停在**模型包围盒**或**交互条**上、输入框持有焦点、在输入框里打字/按回车、点击模型或交互条。有操作时交互条必定可见，并把隐藏截止时间顺延 `barAutoHideSec` 秒；指针离开后从离开那一刻开始计，到点收起。
- 收起态 = `opacity: 0` + `pointer-events: none` + `inert`，沿用已有的 0.18s 过渡；让出下层点击与 Tab 焦点。收起**不是** `barPosition: 'hidden'` 的永久不显示：后者由 `updateBarPosition` 直接 `display: none`，自动隐藏机制在 `hidden` 档下不参与。
- 鼠标移到模型或交互条上立即重新显示（事件驱动：全局 `pointermove` 只在「进入 / 离开」两个边界切换计时；单个 `setTimeout` + 绝对截止时间 `barHideAt`，到点若被延后就按剩余时间重排。不轮询、不堆多个计时器）。
- 首屏交互条出现后从可见那一刻开始计；配置改成 0 立即常显；在设置页改位置或时长时先把交互条显示出来，再按新值重新计时。

## 备选方案

### 每次 pointermove 都重置 setTimeout

- Pros：实现直白。
- Cons：鼠标在模型附近移动时不断 `clearTimeout`/`setTimeout`（高频创建计时器）；用户把指针停在模型上不动，反而会被判成「无操作」。
- Rejected：改用一个绝对截止时间 + 单个 `setTimeout`，只在边界事件与到点时动计时器。

### setInterval / 每帧检查时间

- Pros：逻辑集中在一处。
- Cons：空闲时无谓唤醒，违背本项目「事件驱动、空闲时零进程开销」的约定。
- Rejected。

### 收起时 `display: none`

- Pros：彻底不占布局。
- Cons：没有淡出过渡，重新出现会跳；`display: none` 下 `offsetWidth/offsetHeight` 为 0，会破坏交互条尺寸缓存。
- Rejected：用 `opacity` + `pointer-events` + `inert`。

## 后果

- 交互条默认 10 秒后收起；收起后它自己也点不到，想看输入框就把鼠标移到角色上（或原本交互条所在位置会随模型一起触发显示）。
- 设置项写进 `settings.jsonc`（`barAutoHideSec`），经 SSE config 快照透传给宠物半边；老配置文件缺该字段时回落 schema 默认 10s，`SETTINGS_SCHEMA_VERSION` 不需要 bump。
- 「有操作」判定复用模型包围盒与交互条矩形的缓存几何，不依赖 DOM `hover` 事件（交互条上的 `pointermove` 照常冒泡到 `document`，所以全局监听就能覆盖）；系统 tooltip 等不会干扰计时。
- 隐藏态带 `inert`，键盘 Tab 不会落进看不见的输入框。
- 输入框有焦点时即使指针离开也不会收起——用户可能正在打字；失焦后重新开始计。
