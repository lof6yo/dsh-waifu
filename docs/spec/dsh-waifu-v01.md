# Spec: Live2D 宠物插件（v0.2：内置「简」+ 自定义触摸部位）

用户可感知行为规格。对应 Intent：[`../intent/dsh-waifu.md`](../intent/dsh-waifu.md)。
状态事件与挂载点基于实测（ADR-002）；渲染技术基于 ADR-003；内置模型与自建动作、touchbox 部位见 ADR-014；DSH 0.2.x settings 适配见 ADR-013。

## 1. 概述

DSH Web GUI 中一只悬浮于角落的 Live2D 桌宠，实时镜像当前会话 agent 状态（思考/空闲/出错/完成/交付/等审批），支持**用户自定义触摸部位**（touchbox）互动、任务完成庆祝；台词与动画按**事件**绑定配置（空闲/思考/出错/完成/交付/等审批各配动作组与台词池，去掉了固定人设；后续版本再加入 LLM 人设提示词说话）。内置模型**只有「简」一个**，随插件包分发（动作资源 6 个自建动作，见 ADR-021），开箱即可用。本版设置页不提供模型选择/导入。默认开启、默认右下角、小尺寸、可隐藏。

## 2. 启用与设置

- 插件启用后宠物默认显示在**右下角**（停靠角固定右下角，不可配置；拖动后可自由放置）
- 设置入口：DSH 设置面板顶层「桌宠配置」tab（`settings.section`）；设置持久化到插件私有 `$DSH_HOME/waifu/settings.jsonc`（JSONC；ADR-013）
- 单页设置流程（从上到下，每个 Section 有统一标题与说明）：**显示 → 事件绑定 → 触摸部位 → AI 回复 → 语音 → 开发者选项**（本版只内置「简」模型，不提供模型选择/导入）。「显示」内含三张带标题的卡片：基础显示（开关/尺寸/渲染帧率）、画布与位置（留白/默认位置/归位）、对白气泡（位置与样式）；采用**显式保存**（无自动保存；切模型/离开设置时自动补存）：事件绑定分组在 `eventsDirty/saving/error` 时显示保存状态行（已保存时间/失败原因）；触摸部位按**部位粒度**：只有被改动的部位卡片顶部显示「● 未保存改动 · 保存」，新建/删除/排序等结构变更在分组顶部提示保存
- 设置项：
  - 开关（显示/隐藏）
  - 尺寸滑杆（40–400px，默认 280）
  - **画布留白**：水平/垂直留白（每侧，占尺寸百分比 0–300，默认 125/50）——角色四周留出的可绘制空间，防止大幅动作/物理甩尾被裁切
  - **默认位置（中心点）**：显示区中心点距窗口右边/底边，**按当前窗口画布（视口）宽/高的百分比**取值（0–100，默认 10/0）——首次启动与「归位」时使用；「归位」由宠物半边按视口与画布尺寸计算中心点位置后 `POST /set-display`（只改位置、尺寸不变）；「归位」按钮位于「中心距下」一行右侧
  - **捕捉当前位置**：「归位」右侧的「捕捉」把角色现在的位置换算成上面两个百分比并写成新的默认位置（宠物半边算 `(right + 画布宽/2) / 视口宽`，夹到 0–100）——调好位置后按一下，下次归位/重启就停在这里
  - **表单行布局**：留白 / 默认位置 / 气泡这几张卡是**单行**（label 占满左侧剩余空间、不换行；输入框与按钮靠右固定宽度），比 96px 固定 label 列更省地方；「背景色 / 文字色」两个色块并排成一行
  - **对白气泡**：位置（相对角色包围盒顶部中心的水平/垂直偏移 px，默认 0/24；垂直偏移**正值向上、负值向下**）、背景色/背景不透明度/文字颜色（默认 #ffffff / 92 / #222222）；交互条贴在模型上方且已自动收起时，气泡随之下移贴近模型（最多下移到距包围盒顶部 8px）
  - **渲染帧率**（尺寸下方独立分组，标题「渲染帧率」）：一行三个**自绘圆形单选**（○ 30 / ○ 60 / ○ 不限制帧率；配置值 `maxFps`：`30` / `60` / `0`）；默认 **30**；改档经 SSE **立刻**作用到 PIXI `ticker.maxFPS`，无需重启/刷新
  - **事件绑定**（独立分组，标题「事件绑定」）：6 个事件各配「动作 / 表情 + 入态台词池」；长状态（思考 / 等确认）的后续台词交给 AI 演绎（见「AI 回复」分组）；每张卡可「恢复默认」；改动即时保存并经 SSE 生效
    - 「动作 / 表情」是一个多选下拉：列表内分「动作」「表情」两组，动作组单选（可不选）；表情可多选，只有互斥组内（眼部：星星眼/白眼/泪花/爱心眼/眼泪；皮肤：脸红/脸黑/血）才二选一（ADR-024）。列表与 tag 统一用中文显示名（`Idle`→待机、`Nod`→点头、`ShakeHead`→摇头、`Tilt`→歪头、`Sway`→左右晃），存储仍是英文 id
  - **触摸部位**（独立分组，见 §4）：编辑开关 + 部位/box/台词/动作表情编辑器 + **当前模型状态动画映射**（6 状态，可覆盖内置默认）
  - **交互条**（「AI 驱动 → 触发」卡片内，ADR-034；自动隐藏见 ADR-053）：`barPosition` 三档——模型下方 / 模型上方（默认）/ 不显示，决定「静音 + 对话」条贴在包围盒哪一侧；同一行的数字框是 `barOffset`（px，-200..200，默认 -30），正数把整条往远离模型的方向推、负数可压住模型边缘；其后的数字框 `barAutoHideSec`（秒，0–3600，默认 10，0 = 一直显示）决定**无操作多久后自动收起**——把指针停在模型或交互条上、点击它们、或在输入框里打字/聚焦都算有操作，交互条保持可见并把截止时间顺延；指针离开后开始计时，到点淡出并让出点击；鼠标移回模型立刻重新出现。交互条贴在模型上方并收起时，对白气泡随之下移填补原来的空档，重新出现时气泡回到原偏移。
  - **打断优先级**（「对白气泡」卡片最后一行，ADR-032）：`interactionMode` 三档——触摸优先（默认）/ 互相打断 / 事件优先；决定触摸互动与状态事件谁先占「气泡 + 动作 + AI 演绎」。触摸优先与互相打断下，触摸立刻停掉长状态的演绎与常驻底稿并保持 2.6s，窗口内状态台词 / 状态动作 / 状态类 AI 请求都不抢占；窗口结束后长状态仍在则重新入态继续演绎。事件优先保留旧行为。
  - **AI 回复**（独立分组，ADR-025）：总开关 `aiEnabled`；**「仅触摸」开关 `aiTouchOnly`**（开启后状态变化只用预置台词、AI 只在触摸时发言——状态切换太快时模型来不及出字）；AI 台词上屏后有 1.4s 最短可见时间（期间状态预置台词排队），状态类回复若期间状态又变则丢弃；失败时 `/interact` 回传 `no-reply: <原因>`（ADR-028，便于区分「provider 没配 key / 模型空回复 / 超时」）；开启后 `aiProvider` / `aiModel` 用**下拉**选择（候选来自 Host 的 `ctx.llm.listProviders()/listModels()`，见 `GET /api/dsh-waifu/ai-options`；适配器不提供目录时回落成手填输入框），默认 `openrouter` / `google/gemma-4-31b-it`；**注入对话历史（轮）** 设置项 `aiHistoryCount`（0–50 轮，默认 10；1 轮 = 一问一答两条消息）：把最近的成功往来（情景描述 + 当时台词）拼在当前情景之前一起发给模型，0 = 不注入（ADR-030）；历史里只有**用户行**带时间戳前缀（同一天 `[21:03]`、跨天 `[11/4 21:03]`），assistant 行不带（ADR-049：带时间戳会让模型照抄格式）；当前情景里写明「现在是 11月5日 周四 21:10」，模型据此判断隔了多久；**「全 AI 接管」开关 `aiTakeover`**（ADR-031：不显示任何固定对白，气泡全部来自模型；触摸时连 hint 都不给；长状态「延迟」失效、入态立刻请求，「间隔 / 上限」保留，设置页把延迟输入框置灰）；**人设直接在设置页文本框编辑并「保存人设」**（`GET/POST /api/dsh-waifu/persona`，落盘 `$DSH_HOME/waifu/persona.md`；**不再自动生成模板**——没有文件就用代码里的内置默认，这样升级后默认人设的改进能真正到达老装机；**内置默认可直接用的通用人设**（只写性格与说话方式，不含任何特定玩法）；**人设与插件逻辑解耦**——插件只把它原样放进 system 开头，不解析、不校验、不假设里面写了什么（像换卡带）；想回到内置文案要点设置页的「恢复默认」（= 清空并删掉 `persona.md`，回到内置默认，而不是把默认文案抄进文件——抄进去就又被冻住了）；超 8000 字截断、空白回落默认）
  - **事件文案（ADR-039）**：「触发场景」每个事件除了开关，还有一个文本框可覆写「这件事怎么描述给模型」（留空 = 内置文案，截 60 字；落盘 `eventTexts`，二层路径写入）。历史注入同时改为**一行式短句**（`[16:22] 主人「轻抚」了「脸」`），当前请求仍用完整场景句——历史不再重复整段模板。16 个场景开关默认只开「思考中 / 出错 / 完成 / 交付成果 / 等确认 / 审批通过 / 审批拒绝 / 会话开启」，工具调用五类、会话结束与子代理进出默认关（会话里噪音太大）。
  - **语音**（独立分组，ADR-033）：总开关 `ttsEnabled`；**语音模型** `ttsModel`（下拉，取自 `TTS_MODELS` 目录，只列通义千问 `qwen/qwen-audio-3.0-tts-plus` 与 `qwen/qwen-audio-3.0-tts-flash`；默认 `qwen/qwen-audio-3.0-tts-flash`，走 OpenRouter `/api/v1/audio/speech`，key 取自 DSH 凭据 `OPENROUTER_API_KEY`，不写进插件配置）；**音色** `ttsVoice`（下拉，随所选模型给候选；只收女性音色，默认 `longanlingxi`（另有 `longanyuanfei`、`longanlingxin` 等），见千问 TTS 音色列表）；**口型跟随** `lipsyncEnabled` 与**口型强度** `lipsyncGain`（0–300%，100 = 标准，默认 130）；「试听一句」按钮把样例发到 `POST /api/dsh-waifu/tts` 直接播放，用来确认模型/音色是否合适
  - **动作与表情**（「AI 驱动」内的卡片，ADR-040）：列出当前模型可被模型选用的全部动作（8 个动作组）与表情（11 个，不含「无」；其中「眨眼」是一次性表情，预览时播一遍 `Wink` 动作、不写常驻开关），每行左侧勾选框决定**是否发给模型供选择**（关掉 = 不进提示词目录、模型写出来也会被过滤，默认全开——表情「羞愤」例外，默认不发给模型），行内只显示 `英文 id`（中文名只是显示用，不发给模型），展开可编辑「给模型的释义」——这一句就是拼进 system prompt 的目录行解释，留空用内置释义（≤80 字，回车/失焦即保存，落 `motionTexts` / `expressionTexts`）。布局与「触发场景」一致：折叠头 + 缩进编辑区 + 「已自定义」标记；每行右侧「编辑」后再一个「预览」按钮，点击立刻在角色上播放该动作 / 亮起该表情（同页 CustomEvent `dsh-waifu:preview-catalog`，动作走互动动作通道、表情走 AI 标签的临时表情通道）
  - **开发者选项**（独立分组）：总开关 `developerMode`；开启后显示**调试面板**开关（`debug`）与**显示触摸部位色块**（`showTapZones`；与调试面板可独立开关）
- 调试面板（debug 开启时显示）：从上到下依次是**场景演示**（下拉选任一「触发场景」+「播放」按钮，强制走真实触发链路：台词/动作/表情/语音都由 AI 按该场景即兴决定；跳过场景开关与最小间隔、不占用真实事件的时间预算；AI 总开关关闭时只记日志不触发）、模型原生动画预览（下拉选动作 + 「播放」按钮，改选即预览，按钮可重播）与**表情预览**（下拉选表情 + 「播放」按钮，同一套交互：改选即生效并常驻（一次性表情「眨眼」播一遍即结束），选「无」恢复默认脸），再往下是**控制台**（ADR-043），最底一行是实时状态文本（agent 状态 / 宠物状态 / 版本 / 部位数 / 当前表情 / 位置与尺寸 / 模型与画布尺寸）。面板为**绝对定位浮层**，不占布局、不推动画布。默认**自动跟随**：水平居中于角色模型、浮在其上方（空间不足时贴角色顶部）；面板整体位于模型上方时对白气泡再叠在面板之上；手动摆放后不再影响气泡位置（上下拖动面板不会带着气泡跑）。**自由摆放**（ADR-044）：按住标题栏拖动改位置、拖四角改大小（最小 320×400，整块始终留在视口内，窗口缩放/角色挪动后自动夹回），松手即记进浏览器 localStorage（键 `dsh-waifu.debug-panel:v1`），刷新后回到原处；进入手动摆放后不再跟随模型，双击标题栏恢复自动跟随并清除记录。标题栏右上角按钮是**折叠/展开**（折叠只留标题栏，再点展开恢复原尺寸）；面板默认尺寸按视口给足（宽 320–460、高 400–640 且不超过视口 70%），内容区不出现滚动条，控制台吃满面板剩余高度并在自身内部滚动（ADR-055）
- **显示触摸部位色块**（`showTapZones`）：在模型上叠加当前生效的触摸部位 box（部位名标签；pointer-events:none）；与编辑态共用同一套绘制逻辑
- 宠物悬浮菜单（右键或悬浮时出现）：隐藏、设置、切换到空闲/思考演示动画（调试用）

## 3. 状态镜像（核心）

状态机六态，映射到真实 DSH 事件（ADR-002/012）。**台词与动作由用户在设置页「事件绑定」配置**（未配置的沿用内置默认）：

| 宠物状态 | 触发事件 | 表现（动作/表情 + 气泡） |
|----------|----------|--------------------------|
| 空闲 | `agent/status` status=idle（非刚完成） | 待机动画（默认 `Idle`：呼吸/微摆/眨眼）；偶发瞬态气泡（事件 idle 台词池） |
| 思考中 | `agent/status` status=running | 歪头 `Tilt`；气泡**常驻**：入态台词 → AI 演绎按节奏替换（ADR-026） |
| 出错 | `agent/error` | 摇头 `ShakeHead`；瞬态气泡（事件 error 台词池） |
| 完成 | `agent/turn-stopping` + running→idle 下降沿 | 无动作（保持 `Idle`）；瞬态气泡（事件 done 台词池） |
| 交付 | `session/event` 中 `deliverables/presented` | 无动作（保持 `Idle`，可单独映射）；瞬态气泡（事件 delivered 台词池） |
| （可选）等人确认 / 等审批 | `approval/request`、`user-questions/request` | 左右晃 `Sway`；气泡**常驻**：入态台词 → AI 演绎按节奏替换（ADR-026） |

- 状态变化即时反映（事件驱动，SSE 推送）
- **一轮演绎期间气泡不自动消失**（ADR-052）：台词文字比声音早到，展示时长按「整轮演完」起算，演绎中只换文案不收气泡；一轮结束后再停 2.5 秒消失。此前按「一段文字到达」计时，多段台词会在播到一半时气泡消失、播完又出现。
- **所有气泡都有最长显示时长**（ADR-027）：设置页「对白气泡」的「最长显示（秒）」默认 10、0 = 不限；从「隐藏 → 可见」起算（替换文案不重置），到时连常驻底稿与 AI 演绎一起收掉，防止出态事件丢失 / SSE 断流 / 标签页休眠导致气泡永久常驻
- **长状态气泡与状态同生命周期**（ADR-026）：思考中/等审批期间气泡常驻——先显示入态台词，之后按设置节奏让 AI 演绎替换同一状态的台词（`*AiDelay` 秒后第一次、每 `*AiInterval` 秒一次、每次入态最多 `*AiMax` 次）；AI 失败保留当前文案，出态立即停止计时；入态台词留空且 AI 关闭时不显示气泡
- 空闲/出错/完成/交付为短状态：气泡约 2.5s 后自动隐藏
- **事件绑定体系**（ADR-015，台词部分由 ADR-026 调整）：每个事件 = 动作组候选（随机播一个）+ 入态台词池；内置一套中性中文默认文案；用户可在设置页逐事件覆盖，恢复默认随时可回；人设由 `persona.md` 提供（ADR-025）

### 3.1 待机小动作（ADR-035）

- 空闲（`idle`）时每 7–16s 随机播一个幅度不大但看得清的微动作，避免长时间定格：
  `Glance`（偏头看一眼）、`Perk`（听到动静，抬头挑眉）、`Shift`（换重心）、`Sigh`（叹气）。
- 只驱动头部角度与位移参数：耳朵、尾巴在物理里是纯输出（Output Weight = 100），
  动作直接写它们无效，靠物理链被头部带动才有反应。
- 非 `idle`、正在互动 / 预览、页面不可见时延后 4s 重试；设置页「显示 → 待机小动作」可整体关闭。

### 3.2 触发调度（ADR-047，已实现）

- **一个入口**：触摸 / 对话 / DSH 事件 / 静默超时四类触发都先送到 `src/client/schedule.ts` 的 `dispatchTrigger()`，判断顺序固定为 过滤 → 时间门 → 占用门 → 被拦动作；Host 只上报「发生了什么」（`activity(seq, kind)`），不按频率拒绝。
- **四个动作**：`run`（立刻开一轮，带上一轮攒下的合并项）、`drop`（丢弃，控制台留一行 `dropped | …`）、`defer`（延后补发最后一次，仅触摸连点）、`merge`（并进下一次触发，控制台留一行 `merged | …`）。
- **策略表**（唯一真值）：

  | 触发源 | 间隔 | 上一轮进行中 | 被拦动作 | 可合并 |
  |---|---|---|---|---|
  | 触摸 `tap` | `tapGapMs`（默认 1200ms，0–5000） | 恒打断 | 延后补发 | 否 |
  | 对话 `chat` | 0 | 恒打断 | 丢弃（无） | 否 |
  | 事件 `event` | `aiMinIntervalSec`（默认 1s，0 = 不限） | `triggerMode`：queue 合并等说完 / interrupt 抢占 | 间隔内合并 | 是 |
  | 静默 `idle` | 0（时机由 `idleTimeoutSec` 决定） | 恒丢弃 | 丢弃 | 否 |

- **两种窗口分工**：同类聚合 `activityWindowSec`（默认 10s：同 kind 的事件在窗口内聚成一条并记次数）与事件最小间隔 `aiMinIntervalSec`（任意事件两次触发之间的最小时间差）。两者都是**合并**，键不同（同类 vs 任意）。
- **合并轮何时补发**：`merge` 只往队列里攒；补发有两个时机——当前轮结束那一刻（`startTurn` 收尾），或最小间隔到期（定时器）。上限 `mergeMax`（默认 6 条，1–20），超出丢最旧并记 `merge overflow`。因此一次事件风暴的可见结果是「立刻一轮 + 补发一轮」，而不是中间全丢。
- **唯一的绕过**：调试面板「场景演示」走 `force`，直接开一轮，不进策略表、也不改窗口状态。
- **每次丢弃都有痕迹**：控制台能看到 `dropped` / `deferred` / `merged` 三类记录，用户不必猜「为什么没反应」。

## 4. 触摸互动（用户自定义 touchbox）

### 4.1 部位抽象

- 每个部位 = `name`（展示名）+ `boxes[]`（一到多个矩形）+ `interactions[]`（自定义交互，ADR-038）
- 每条交互 = `name`（用户自由命名，≤20 字，原样告诉模型）+ `trigger`（`tap` 单击 / `double` 双击 / `hold` 悬停停留）+ `holdMs`（仅悬停，默认 3000ms，300–10000ms 可调）；单部位最多 8 条。悬停停留 = 鼠标停在部位 box 内 ≥holdMs 自动触发（移出/按下重置，单趟一次），不需要点击；按压路径只判定单击/双击。部位没配交互（或没有匹配的触发条件）→ **不触发**（点了没反应）。场景句统一为「主人「<交互名>」了你的「<部位>」」（单击/双击/停留的差别不进场景句），模型按字面理解这个交互名
- 每个 box = `{left, top, right, bottom}`，为**相对模型包围盒**的 0–1 归一化坐标（左上右下）——这是存储/判定格式；设置页输入按**左下角为原点**的百分比展示（上 = box 上边离底边的距离，调大即往上长；下 调小即往下长），越界自动夹到 0–1，左右/上下颠倒自动交换，零面积 box 丢弃；单部位最多 12 个 box
- **图层**：部位列表顺序即图层顺序，**第 0 项为最上层**；设置页可上移/下移调整（保存按该顺序持久化）
- 命中判定：点击点换算到包围盒比例坐标 (nx, ny)；**按图层顺序从上到下遍历**，返回第一个命中任意 box 的部位（box 重叠时上层部位生效）；未命中不响应
- 命中检测不再依赖模型 HitArea，也不再使用旧的「空间回退阈值分档」（spatialTap 已移除）

- 活动提示（ADR-036，与状态正交、不写气泡）：工具执行、审批批准/拒绝、会话开关、子代理进出各播一个短动作（`tool-read→Glance`、`tool-write→Perk`、`tool-run→Shift`、`tool-agent→Nod`、`tool-other→Tilt`、`approval-granted→Nod`、`approval-denied→ShakeHead`、`session-open→Perk`、`session-close→Sigh`、`subagent-start→Glance`、`subagent-end→Nod`）；NORMAL 优先级，不压状态与触摸。**Host 不再节流**（ADR-047）：同类事件由客户端调度器按 `activityWindowSec` 合并，超出的不会丢，只是并进下一轮场景句

### 4.2 命中后的表现

- 台词选择：部位配置了**自定义台词**（`part.lines`）→ 从该部位台词池随机选一条（避开同一部位上一条）；**未配置 → 不显示气泡，只播该部位动作**（不再有固定人设台词池兜底）
- 动作：部位 `motions` 里的动作组以 FORCE 优先级播放（可打断状态动画与上一次互动；`motionFinish` 后回到当前状态动画）；没有动作组则只出气泡
- 点击/拖动判定：按下后移动 ≤ 6px 松手 = 点击（触发互动）；> 6px = 拖动（取消本次互动）
- 防刷屏：点击互动 80ms 防抖；每次有效点击立刻换一条随机台词并重播动作，同一池内避开上一条
- 表情：部位 `motions` 里的表情 id（可多个，ADR-024）会全部切过去并保持 2.2s，然后回到当前事件绑定的表情；不会打断正在播的动作
- AI 台词（ADR-025，`aiEnabled`）：命中部位先显示预置台词，同时 POST `/api/dsh-waifu/interact`（`{kind:'tap', part, hint}`）；Host 用 `ctx.llm` 生成一句（≤60 字、单行）后替换气泡；请求失败/超时/模型无回复则保持预置台词。状态变化同理（`{kind:'state', state, hint}`，仅非 idle）
- **语音与口型（ADR-033，`ttsEnabled` + `lipsyncEnabled`）**：开启语音后 AI 台词改走 `POST /api/dsh-waifu/speak`（SSE：`clause` 段文字 + `audio` 段音频）——每段音频**开始播放时**气泡才补上那一段文字，所以看到的字与听到的声音永远同段；`ParamMouthOpenY` 由同一段音频的时域波形能量驱动（张得快、收得慢），口型强度受 `lipsyncGain` 调节。语音关闭、或流里一句都没出（禁用/冷却/零文本）时自动回落上面的一次性 `/interact`；个别段合成失败只是没声音，文字照常上屏。触摸时顺手解锁 `AudioContext`（浏览器自动播放策略）
- **交互条（ADR-034）**：模型包围盒上方或下方居中一条胶囊，左侧圆形按钮切换语音（写 `ttsEnabled`），右侧输入框回车（或点右侧圆形提交按钮）把这句话交给模型（`kind: 'chat'`），回复与触摸共用气泡 / 语音 / 口型 / 历史；`barPosition` 决定贴上还是贴下、`barOffset` 再沿该侧推开若干像素；静音按钮是内联 SVG 图标（不用 emoji）；AI 关闭时输入框禁用；交互条上的指针事件不参与拖拽与点击互动。**自动隐藏（ADR-053）**：无操作 `barAutoHideSec` 秒（默认 10，0 = 常显）后收起为 `opacity: 0` + `pointer-events: none` + `inert`，鼠标移到模型或交互条上立即重新出现；指针在模型/交互条上或输入框有焦点时不收，离开/失焦后重新计时；`barPosition: 'hidden'` 时本机制不参与。交互条贴在模型上方并收起时，气泡随之下移填补空档（下移量 = 交互条高出模型顶部的那段，最多贴近到距包围盒顶部 8px），交互条再出现时气泡回到原偏移。
- **打断优先级（ADR-032，`interactionMode`）**：触摸互动与状态事件共用同一条「气泡 + 动作 + AI 演绎」通道，规则由设置项决定——`touch-first`（默认）触摸立刻接管，停掉长状态的演绎计时与常驻底稿并保持 2.6s，窗口内状态台词 / 状态动作 / 状态类 AI 请求都不抢占，窗口结束后长状态仍在则重新入态继续演绎；`mutual` 触摸立刻接管，但状态一变就立刻收回；`event-first` 触摸不打断长状态演绎，只播自己的表情 / 动作
- 互动动画可打断当前状态动画与上一次互动；**演出期间（动作播放中或临时表情保持中，ADR-041）抑制鼠标跟随**，两者都结束后再恢复（演出时头眼回正前方，不跟着鼠标飘）
- 拖动：实时跟随指针，拖拽中暂停气泡与触摸互动；松手后停留并持久化位置（right/bottom）；可拖到窗口任意位置、允许一半移出窗口，但**宠物画布中心点始终被约束在视口内**（不会拖丢）
- **点击穿透**：宠物画布/容器的透明区域 `pointer-events: none`，点击直接落到下层 DSH UI；只有当前触摸部位的 box 范围（以及无部位时模型包围盒）接收点击/拖动，不会用一张大画布挡住界面
- 鼠标跟随（默认开启）：鼠标移动时头/眼睛/身体平滑看向鼠标；**只在模型包围盒外扩「跟随范围」（% 模型尺寸，设置项「显示 → 跟随范围」，默认 100%，0 = 只在模型框内）的矩形内才跟随**，出范围回正前方；拖拽中/页面失焦/宠物隐藏时不跟随；移出页面复位

### 4.3 编辑态（设置页「触摸部位」）

- 触摸部位分组「预览 box（在角色上显示）」开关 → 宠物进入**预览态**：强制可见（即使开关为隐藏，退出后恢复）、叠加显示当前草稿的所有 box（部位名标签 + 不同颜色；当前展开部位高亮）；预览只影响显示，不影响编辑与保存；**预览态下点击角色可用草稿 box 正常触发部位台词/动作**（便于边调边试）
- 部位编辑操作：
  - **新建部位**：输入部位名称（最多 24 字）；新部位初始无 box，可继续添加
  - **添加 box**：输入 `左 / 上 / 右 / 下` 四个值，单位为**模型包围盒百分比（0–100，整数）**，存储时除以 100；box 随输入**实时显示在角色上**（无需保存）
  - **一个部位可对应多个 box**；可删除单个 box、删除整个部位
  - **台词**：每个部位可填自定义台词（多行，一行一条；留空 = 该部位只播动作、不出气泡）
  - **动作 / 表情**：部位建立后，可为该部位选一个动作组 + 一个表情（同款**多选下拉**，列表按「动作」「表情」分组；不选 = 只出气泡；动作选中后触摸时播放，表情持续到下一次切换，ADR-023/024）
  - **图层排序**：部位卡片带「↑ 上移 / ↓ 下移」与层号（统一显示为 `#数字`，#1 = 最上层；叠层说明写在分组标题下的描述里），列表从上到下 = 顶层到底层；新建部位插入最上层
  - **状态动画映射（当前模型）**：6 个状态槽位各可多选动作组（含内置「简」），保存为该模型的状态动画覆盖层；未配置的槽位沿用内置默认
- 任何草稿变更即时反映到宠物叠加层（预览开启时，未保存也实时）；改动按**部位粒度**标记未保存（卡片顶部「保存」按钮），点保存写回 `$DSH_HOME/waifu/touch-parts.jsonc`（或切换模型/离开设置时自动补存）；保存成功后短暂显示「已保存 HH:MM:SS」
- 关闭预览后宠物恢复常规显示；当前模型切换时自动退出预览并载入新模型的部位（未保存改动先自动补存）
- 用户未保存过部位时，使用内置默认部位（「简」：脸/头发/胸/私处/臀/腰/大腿/手/小腿/脚 十个部位，每个部位自带按手感命名的自定义交互——单击 / 双击 / 悬停 3s 三条，如「脸 = 捏/亲/抚摸」「头发 = 梳/抓住/抚摸」，见 presets.jsonc）；保存后以用户文件为准
- 部位数据（含「保存过」状态）经 SSE 随快照下发，宠物即时使用新部位判定

### 5.1 台词与标签契约（ADR-037 / ADR-049 / ADR-050）

一轮回复的正常形状是一行：`<表情>[动作]台词`
——**表情用尖括号、动作用方括号**，两个都可以省略（ADR-050）。目录里每个 id 的释义也按同一形状写，
`<blush>` 与 `[Nod]` 分别对应「改脸/改眼」与「动作组」，取值只能在目录内。

- 外壳只是意图、目录说了算：`<Nod>`、`[blush]` 这类写错壳的仍按目录归位（老历史、手滑不至于失效）。
- 契约由宿主收敛：`filterTags()` 把表情、动作各截到「最后一个」——多写的按后写的算，
  与互斥组同一套规则；宁可只演一个，也不要第二个把第一个拦腰打断。
- 迁移期两代共存：老客户端只认 `tags` 帧、老 Host 只会发 `[表情]`，两种外壳都能解析。
- 正文只取第一行：气泡、朗读都只念这一行，标签全部剥掉；流式期间尾部没闭合的标签先扣住（`[No`、`<blu`），不露半个。
- 另起一行的 `[记] …` 是记忆（不念、不上屏）；`done`/`clause` 文本里不会出现。
- 场景句只写事实（`现在是 …。主人「X」了你的「Y」。`），不带播放器口令；历史里只有主人那侧带时间戳，
  assistant 行记带标签原文（`<blush>[ShakeHead] 别…`），模型从自己的历史里看到格式正例。
- 采样：`temperature = 0.9`、`maxTokens = 160`（上限不是目标）；`finish = length` 时台词补 `…`。
- 合并事件只写事实：调度器交 `{ event, count }`，剧本引擎翻成「（连着 N 次）」，UI 标签不进提示词。

### 5.2 说话时的身体语言（ADR-035）

口型张开量同时带动 3° 以内的点头、0.12 以内的挑眉与轻微眼球下压，随「口型跟随」开关生效。
写值发生在 `InternalModel.update()` 之后，只做视觉叠加，不触发物理重算。

## 6. 模型清单与加载

- **本版只内置「简」**（`presets.jsonc` 唯一一条，`modelUrl: /waifu-assets/models/jian/简.model3.json`）；不提供模型选择/导入 UI（自定义模型能力暂不对用户暴露，后续版本再考虑）：
  - 模型资源**随包分发**在 `assets/models/jian/`（moc3、纹理、physics3、cdi3、model3.json、motions）
  - 动作组共 **10 个**（`scripts/gen-jian-motions.mjs` 幂等生成；ADR-021）：
    - `Idle`（循环 5s）：呼吸 + 微摆 + 眨眼
    - `Nod` 点头 1.5s / `ShakeHead` 摇头 1.6s / `Tilt` 歪头 2.0s / `Sway` 左右晃 3.0s：只驱动头部角度、头部平移与表情，身体由物理链自然跟随
    - `Glance` 瞥一眼 / `Perk` 竖起耳朵 / `Shift` 换重心 / `Sigh` 叹气：活动类事件的短动作
    - `Wink` 眨眼 1.2s（非循环）：一次性表情「眨眼」的落地动作（ADR-054），不走 AI 动作目录
    - ADR-018 那批「受击反应 / 人设小动作」已证明与物理打架（ADR-019/020）；「上下轻跳」因为模型没有可驱动的根位移参数、客户端补位移也不自然，已删除
  - 动作只用 cdi3 白名单参数（角度 / 眼开闭 / 眼笑 / 眉毛 / 嘴形 / 嘟嘴 / 眼球），不驱动 `ParamSwitch*` 表情开关；`model3.json` 另声明 `EyeBlink`（ParamEyeLOpen/ROpen）与 `LipSync`（ParamMouthOpenY）参数组；身体/胸/胯参数是物理输出（Output Weight 30–100），**动作只驱动物理输入**（头部角度与平移，ADR-019）
  - 默认事件动画映射：`idle→Idle`、`thinking→Tilt`、`waiting→Sway`、`error→ShakeHead`、`done/delivered` 不挂动作；默认触摸部位不挂动作（只出气泡）。用户可在设置页逐项改
  - 许可标注：作者「用户自备模型」、许可类型「用户自备模型（随包内置；公开分发前请确认模型授权）」
- 素材经 Host 同源 `/waifu-assets/*` prefix 路由提供（带目录穿越防护；moc3/json/png 等 MIME 正确）
- 动作组选项来自当前模型 `.model3.json` 的 `Motions`（设置页事件绑定与触摸部位共用同款多选下拉），解析失败时可保存但无动作可选
- 旧配置里失效的内置模型 id（如 `hiyori`）自动回退到「简」，升级不出现空白
- **加载失败兜底**：显示静态头像占位 + 错误气泡提示，不影响 GUI 其它功能

## 7. 性能与不打扰

- 渲染清晰度：按设备像素比（上限 2x）放大渲染缓冲 + antialias，避免 Retina 上 1x 缓冲放大产生锯齿；触摸部位叠加层同倍率缩放绘制
- 显示区域留白：画布在模型显示尺寸外加留白（设置项「画布留白」水平/垂直，默认 125%/50% of size），避免大幅动作/物理甩尾（如尾巴）在边缘被裁切；「尺寸」仍指模型可见宽度
- 调试面板（开发者选项）内的「控制台」（ADR-043）：点「开始记录」后**按真实发生顺序**逐条追加一次反应的全过程——
  `trigger`（这轮由什么触发，完整 TriggerBody）→ Host 在报文真正发出/收全的时刻推来的 `debug` 帧
  （`llm.request` 完整请求 JSON：provider/model/temperature/maxTokens/system/每条 messages；
  `llm.reply` 模型完整原始输出（含 `[表情][动作]` 标签与 `[记]` 行）；
  `tts.request` 完整请求体 JSON：endpoint/model/input/voice/是否命中缓存；`tts.reply` 摘要 bytes/mime/cached/ms）
  → `clause`/`tags`/`memory`/`done` 帧 → 播放落地（`play.expression` / `play.motion` 实际应用的表情与动作、
  `play.audio` 每段实际播放时长、`interact.result`）。
  顺序即到达顺序：`/speak` 用 SSE `debug` 帧实时下发，`/interact` 在响应里回带 `trace` 数组（语音关闭时一次性补进）。
  `audio` base64 只报字节数、逐字 `text` 增量不记；单行上限 20000 字、最多 300 行、贴底自动滚动；
  可视区域**固定 20 行高**（行高 16px，内容超出在框内滚动）；「停止记录」只暂停追加、已记录内容保留（用「清空」清除）；
  「复制」把当前全部记录按行拼成纯文本一键进剪贴板（含时间与标签，无内容时按钮提示「无内容」）；关闭面板即清除
- **只有标签页隐藏 / 窗口最小化时暂停渲染循环**（保留最后画面，ADR-042）；窗口失焦（点到别处、切到别的应用）不停渲染，角色继续动，只暂停鼠标跟随
- 页面隐藏时**不发任何 AI 请求**（活动触发直接丢弃、静默计时器不挂），并中断在跑的 `/speak` 流（服务端 TTS 随之取消）；关掉网页后客户端销毁，不会有任何 LLM/TTS 调用
- 渲染帧率由 `maxFps` 控制（默认 30；可选 60 / 0=不限制）；尺寸变更经 rAF 合并落地
- WebGL 不可用或 FPS 持续过低：自动降级为静态头像模式
- 一键隐藏后完全不渲染（零开销）；隐藏状态持久化；默认小尺寸、右下角，不遮挡主操作区

## 9. 技术边界（实现约定，非用户行为）

- 渲染：pixi-live2d-display 0.4.0 + PixiJS 6.5.10 + Cubism Core 4（ADR-003）
- 挂载：Client Slot `shell.overlay`；设置入口：Client Slot `settings.section`（ADR-002）
- 设置：插件私有 `$DSH_HOME/waifu/settings.jsonc`（ADR-013；DSH 0.2.x `ctx.settings` 不再是 namespace 注册表，写入会触发整插件重载；`settings.configure({auto:false})` 隐藏自动表单页）；读写经 `/api/dsh-waifu/settings`（GET `{value,error,path,writable}` / POST `{ops}`）
- 状态源：Host 订阅 `agent/status`、`agent/error`、`agent/turn-stopping`、`approval/request`、`user-questions/request`（ADR-002）；交付态订阅 `session/event` 的 `deliverables/presented`（ADR-012）
- 状态传输：Host→Client 同源 SSE `/api/dsh-waifu/events`（快照 + 变更推送 + 30s 心跳，ADR-006）；首帧走 `GET /api/dsh-waifu/state`
- **事件绑定**（ADR-015）：`EventBindings`（`models.ts`）随 `PetStateView.config.events` 下发；默认台词常量 `DEFAULT_EVENT_BINDINGS` + 模型 `animationMap` 提供动作组，用户覆盖存 `touch-parts.jsonc` 的 `models[<id>].events`（整事件替换）；无固定人设，后续 LLM 人设走提示词
- **模型与素材**：内置模型随包（`assets/models/jian/`），`/waifu-assets/*` prefix 路由（目录穿越防护）；本版 UI 不暴露模型选择/自定义模型
- **触摸部位**（ADR-014）：`TouchPart`/`TouchBox` 共享类型与纯函数（`normalizeTouchParts` / `pointToBoundsRatio` / `hitTestTouchParts`）在 `src/models.ts`；Host `TouchPartsStore` 读写 `$DSH_HOME/waifu/touch-parts.jsonc`（按模型 id 分组：`parts` + 可选 `animationMap` 覆盖层；未保存回退内置默认）；client 设置页与宠物层通过 `window` CustomEvent（`dsh-waifu:touch-edit`）传递编辑态与草稿部位；宠物层用 `model.getBounds()` 换算 box 到画布坐标绘制叠加层
- **文字先到、声音后到**（ADR-048 P5）：台词文本一到达就上屏，动作/表情等该段音频开始播时才执行——气泡不再等 TTS 合成完
- **标签可以写在台词中间**（ADR-048 P4）：`[blush]唔…别、[Nod]别戳了啦` —— 脸红从头到尾，摇头只跟后半句；Host 把标签剥掉并挂到它所属的段，正文里不会出现方括号
- **一段一个演出**（ADR-048 P3）：模型给的标签按「段」执行——表情设了就保持到下一个表情或本轮结束，动作排队一个个播（最多排 2 个，多了丢最旧的并在控制台留 `cue.dropped`）；同一轮不会出现「动作刚起就被自己打断」
- **演出谱子**（ADR-048）：Host 把台词切成段后，每段 `clause` 帧带 `{ index, text, cues }`——`cues` 是这一段该执行的表情/动作（P2 起下发，旧客户端忽略该字段仍按 `tags` 帧播）；段序号即音频序号，口型/气泡/动作共用同一条时间线
- 动作管理：pixi-live2d-display `MotionPriority`（IDLE=1 / NORMAL=2 / FORCE=3），idle 用 IDLE、状态与互动用 FORCE；重播同一动作前先 `stopAllMotions()`；完成信号统一用 `motionFinish`（ADR-008）
- focus 抑制：非 idle 动作播放期间 `focusController.focus(0, 0, true)` 归零 + `pointermove` 门控，`motionFinish` 后恢复（ADR-008）
- 动画映射：`resolveMotionMap()` 合并 `DEFAULT_MOTION_MAP` + 自定义条目/内置 preset；状态槽位 6 个；部位动作走 `part.motions`（ADR-014）
- 自建动作：`scripts/gen-jian-motions.mjs`（纯 Node，无三方依赖）幂等生成 motion3.json，自动计算 Meta 计数并校验参数 ID 存在于 `简.cdi3.json`
